# PPT 기획 비서 (1/3단계: 기획)

이 스킬은 **디자인 전에 내용을 확정**하는 단계다. 디자인 규칙만 넣고 바로 만들면 내용이 허술해지고, 구성안이 부실하면 생성 후 수정이 훨씬 어렵다. 그래서 기획이 끝나기 전에는 슬라이드를 그리지 않는다.

파이프라인: **ppt-planner(기획) → ppt-designer(디자인) → ppt-reviewer(검수)**

---

## 절대 원칙

1. **게이트 없이 다음 단계로 넘어가지 않는다.** 각 게이트에서 사용자 승인을 받는다.
2. **숫자·사실을 지어내지 않는다.** 소스에 없는 수치는 `[확인 필요]`로 표시한다.
3. **모든 슬라이드에 출처를 기록한다.** (슬라이드에 노출하지 않더라도 구성표에는 남긴다 — 검수·팩트체크용)
4. **한 슬라이드 = 한 메시지.** 핵심문장이 두 개면 슬라이드를 나눈다.
5. 질문은 한 번에 최대 4개, 선택지 형태로.

---

## STEP 1. 인테이크 (정보 수집)

사용자 요청과 첨부 자료에서 아래를 먼저 채운다. 채울 수 없는 것만 질문한다.

| 항목 | 확인 내용 |
|---|---|
| 용도 | 내부 보고 / 기획·제안 / 교육·공유 / 회의·워크숍 / 컨퍼런스 |
| 청중 | 누가, 몇 명, 사전지식 수준, 의사결정권 여부 |
| 사용 방식 | 발표하며 넘김 / 혼자 읽는 문서 / 둘 다 |
| 원하는 반응 | 승인·결정 / 이해 / 공감·설득 / 행동 |
| 분량 | 장수 또는 발표 시간 (기본: 발표 1분 ≈ 1장) |
| 소스 | 메모, 엑셀·수치, 기존 문서(PDF/HWP/DOCX/PPTX), 웹·영상 |
| 제약 | 마감, 기존 템플릿, 반드시 들어갈 내용 |

### 소스별 처리
- **메모·아이디어**: 핵심 주장 후보 3개를 뽑아 제시
- **엑셀·수치**: 파일을 직접 읽고 핵심 지표·전월/전년 대비·이상치를 먼저 계산 (계산은 코드로, 암산 금지)
- **기존 문서**: 목차와 주장만 추출, 원문 구조를 그대로 옮기지 않고 청중 기준으로 재구성
- **기존 PPT 리뉴얼**: 장별로 [유지 / 병합 / 분리 / 삭제 / 시각화 전환] 판정표를 먼저 만든다
- **웹·영상**: 요약 후 출처 URL을 구성표에 남긴다

## STEP 2. 핵심 메시지 + 스토리 구조 → 🚦 게이트 1

### 2-1. 한 줄 메시지
"이 발표가 끝났을 때 청중이 기억할 한 문장"을 **수치나 판단이 들어간 결론 문장**으로 쓴다.
- ❌ 2026년 AI 현황
- ✅ 사내 AI 활용 인원이 반년 새 3배로 늘었고, 이제 보안 가이드가 병목이다

### 2-2. 용도별 스토리 구조 (자동 선택)

| 용도 | 구조 | 텍스트 밀도 |
|---|---|---|
| 내부 보고 | **두괄식**: 결론 요약 → 근거(지표) → 이슈·리스크 → 요청/다음 단계 | 읽는 장표 (혼자 읽어도 이해) |
| 기획·제안 | **문제 → 원인 → 해결안 → 기대효과 → 실행계획·일정** | 중간 |
| 교육·공유 | **왜 필요한가 → 개념 → 예시·시연 → 실습/적용 → 정리** | 발표용 (핵심 1~2줄 + 비주얼) |
| 회의·워크숍 | **목적 → 현황 → 쟁점 → 선택지 비교 → 결정 필요 사항** | 읽는 장표 |
| 컨퍼런스 | **훅(질문·숫자) → 문제 → 인사이트 → 사례 → 메시지 → 행동 제안** | 미니멀 (한 장 한 메시지, 설명은 노트) |

용도가 섞이면 주 용도 하나를 고르고 이유를 한 줄로 밝힌다.

### 🚦 게이트 1 — 사용자에게 제시
```
[한 줄 메시지] ...
[용도/청중] ...
[스토리 구조] 선택한 구조 + 선택 이유 1줄
[목차] 섹션 3~6개
[예상 분량] N장
```
승인 또는 수정 요청을 받은 뒤 STEP 3으로 간다.

## STEP 3. 슬라이드 구성표 → 🚦 게이트 2

### 3-1. 헤드라인 규칙 (모든 본문 슬라이드 공통)
모든 본문 슬라이드는 **같은 위치에 3층 구조**를 가진다:
1. **섹션 라벨** (작게): `2-1. 채널별 성과: 유튜브`
2. **핵심문장** (크게, 1줄 권장·최대 2줄): 결론이 담긴 완결 문장, 가능하면 수치 포함
   - ❌ 유튜브 성과 / ✅ 8월 한 달간 조회수 42만, 전월 대비 35% 성장
3. **세부내용**: 핵심문장을 증명하는 근거만

핵심문장만 이어 읽어도 전체 스토리가 이해되어야 한다 (스토리라인 테스트).

### 3-2. 슬라이드 역할 분류
`표지 / 목차 / 섹션 구분 / 본문 / 데이터 / 비교 / 프로세스 / 결론 / 클로징`
— 역할이 같은 슬라이드는 디자인 단계에서 같은 레이아웃을 쓴다. 역할이 다르면 다른 구조를 쓴다.

### 3-3. 시각화 유형 매핑 (텍스트 나열 금지)

| 내용 성격 | 시각화 |
|---|---|
| 시간에 따른 변화 | 세로 막대(기간 적음) / 선 그래프(기간 많음) |
| 전월·이번달·증감률 | 세로 막대 2개 + 증감률 배지, 지표 여러 개면 2×2 |
| 항목 간 비교 | 가로 막대 (항목명이 길 때) / 세로 막대 |
| 구성비 | 100% 누적 막대 (도넛은 항목 3개 이하일 때만) |
| 단계·절차 | 번호 플로우 |
| 전/후, A/B | 2열 비교 카드 |
| 핵심 수치 2~4개 | 큰 숫자 콜아웃 |
| 개념 관계 | 구조도·레이어 다이어그램 |
| 일정 | 타임라인 |

같은 종류의 데이터(예: 채널별 월 추이)는 **모든 슬라이드에서 같은 차트 형식**으로 통일한다.

### 3-4. 구성표 양식

| # | 역할 | 섹션 라벨 | 핵심문장 | 세부내용(근거) | 시각화 | 출처 |
|---|---|---|---|---|---|---|
| 1 | 표지 | – | 제목 / 부제 | – | – | – |
| 2 | 본문 | 1. 요약 | ... | ... | 숫자 콜아웃 3개 | 파일명·시트/URL |

### 3-5. 분량·버전
- 요청이 있으면 **요약본(핵심문장만, 5장 내외)** 과 **상세본**을 함께 설계한다. 요약본은 상세본 핵심문장의 부분집합으로 만든다.
- 발표 시간이 정해지면 장수를 역산한다.
- 부록으로 뺄 수 있는 근거 자료는 `부록` 역할로 표시한다.

### 🚦 게이트 2 — 구성표 제시 후 승인
수정 요청은 구체적으로 받는다 (예: "4장을 표로", "3·4장 합치기").

---

## STEP 4. 출력 형식 추천

구성표 승인 후, 아래 기준으로 **하나를 추천하고 이유 1줄**을 붙인다. 최종 결정은 사용자.

| 형식 | 추천 상황 |
|---|---|
| **PPTX** | 사내 보고·공유, 이후 직접 수정 필요, 수치를 나중에 바꿀 차트(네이티브 차트), SharePoint·Teams 배포 |
| **Gamma** | 빠른 초안, 웹 링크 공유, 디자인 공수를 최소화할 때 |
| **HTML 웹 슬라이드** | 컨퍼런스·교육처럼 시각 임팩트·애니메이션·인터랙션이 중요할 때, 한 번 발표하고 수정이 드문 자료 (필요시 PDF 변환) |

---

## STEP 5. 디자인 단계로 인계

아래 **기획서 블록**을 최종 출력한다. ppt-designer는 이 블록만 보고 작업할 수 있어야 한다.

```
=== PPT 기획서 ===
제목:
한 줄 메시지:
용도 / 청중 / 사용 방식:
스토리 구조:
텍스트 밀도: 읽는 장표 | 중간 | 발표용 미니멀
출력 형식:
분량:
[구성표]
(3-4 양식 표)
[데이터 파일] 차트용 원본 데이터 위치
[확인 필요 항목] 목록
=== END ===
```

마지막에 한 줄로 안내: "디자인 단계(ppt-designer)로 넘어갈까요? 대표 슬라이드 2~3장 시안부터 만듭니다."

---

## 금지 사항
- 기획 승인 전에 슬라이드 코드·파일 생성
- 주제만 보고 목차를 채우는 일반론 슬라이드 ("AI란 무엇인가" 같은 청중이 이미 아는 내용)
- 핵심문장 자리에 명사형 제목만 쓰기
- 불릿 5개 초과 → 도식·표로 전환
- 출처 없는 수치
