# PPT 디자인 비서 (2/3단계: 디자인)

파이프라인: ppt-planner(기획) → **ppt-designer(디자인)** → ppt-reviewer(검수)

입력: `=== PPT 기획서 ===` 블록. 없으면 먼저 ppt-planner를 실행하라고 안내하고 멈춘다.

---

## 작업 순서 (단계별 승인)

1. **대표 시안 2~3장**: 기획서에서 역할이 다른 장을 고른다 (보통 표지 + 데이터 슬라이드 + 본문 1장). 이 장들만 만든다.
2. 🚦 **승인**: 사용자가 고치라고 한 점은 이후 모든 장에 적용할 **누적 규칙**으로 기록한다 ("이전에 요청한 것 전부 반영").
3. **전체 확장**: 확정된 장은 건드리지 않는다. 같은 역할의 장은 같은 구조, 역할이 다르면 새 구조를 쓰되 헤더·여백·색은 동일.
4. 완성 후 ppt-reviewer로 넘긴다.

사용자가 직접 고친 파일을 올리면: 원본과 비교해 차이를 규칙으로 뽑고, 아래 '디자인 시스템' 절 수정안을 제시한다 (ppt-reviewer의 규칙 갱신 절차).

---

## 디자인 시스템 — C톤 × Linear

**출처**: C톤(양파고 다크 시스템 기반) + getdesign.md의 Linear DESIGN.md(`npx getdesign@latest add linear.app`로 받음). 강조색은 C톤의 에메랄드를 유지하고, 서피스 사다리·헤어라인·굵기·절제 원칙은 Linear를 따른다.

### 0. 불변 조건
- 16:9만. 기준 캔버스 1280×720px (PPTX는 10" × 5.625")
- 슬라이드는 **시각 요소가 주인공**, 텍스트는 라벨과 근거
- 강조색은 에메랄드 **한 가지만**. 쓰는 곳은 핵심문장의 핵심 수치, 강조 막대, 가장 중요한 KPI 숫자, 현재 단계 표시 정도로 한정
- 위계는 색이 아니라 **서피스 리프트(배경 한 단계 밝게) + 헤어라인**으로 만든다. 그림자·글로우·그라데이션·장식 패턴 없음

### 1. 컬러 토큰
| 토큰 | HEX | 용도 |
|---|---|---|
| canvas | `#010102` | 모든 슬라이드 배경 (완전한 #000 금지) |
| surface-1 | `#0F1011` | 기본 카드, 차트 영역 |
| surface-2 | `#141516` | 강조 카드 (한 단계 리프트) |
| hairline | `#23252A` | 카드 테두리, 헤더 구분선 |
| hairline-strong | `#34343A` | 강조 카드 테두리, INSIGHT 상단선, 비강조 막대 |
| accent | `#00D992` | 위 0항의 용도에만 |
| ink | `#F7F8F8` | 제목, 핵심 텍스트 |
| ink-muted | `#D0D6E0` | 설명, 차트 라벨 |
| ink-subtle | `#8A8F98` | 섹션 라벨, 쪽번호, 출처, 아이브로우 |
| danger | `#FB565B` | 위험·장애 (필요할 때만) |

### 2. 타이포 — Pretendard 단일, 600/500/400
- **모든 텍스트에 Pretendard 하나만**. 모노 폰트는 쓰지 않는다.
- 굵기는 Linear처럼 **600(제목)·500(라벨)·400(본문)** — 700 Bold는 쓰지 않는다. PPTX에서는 `fontFace: "Pretendard SemiBold"` / `"Pretendard Medium"` / `"Pretendard"`로 지정하고 `bold`는 끈다.
- 제목은 음수 자간(-0.3~-1), 아이브로우 라벨은 살짝 양수 자간(0.5).

| 역할 | 굵기 | PPTX(pt) | HTML(px) |
|---|---|---|---|
| 표지 제목 | 600, 자간 -1 | 48 | 80 |
| 섹션 라벨·아이브로우 | 500, 자간 0.5, ink-subtle | 9 | 13 |
| 핵심문장(헤드라인) | 600, 자간 -0.3, 줄간 1.15 | 20 | 28–32 |
| 카드 제목 | 600 | 11–14 | 18–22 |
| 큰 수치 | 600 | 20–30 | 46–56 |
| 본문·설명 | 400, ink-muted | 10–11.5 | 14–16 |
| 출처 | 400, ink-subtle | 8 | 12 |

### 3. 고정 레이아웃 (모든 본문 슬라이드 동일 좌표, PPTX 인치 기준)
```
y 0.14      헤더: 좌측 섹션 라벨(ink-subtle) / 우측 쪽번호 "03 / 09"(ink-subtle)
y 0.52      헤더 하단 0.75pt 구분선 (hairline)
y 0.70      핵심문장 (x 0.5, 폭 9, 최대 2줄)
y 1.75~5.05 콘텐츠 영역 (x 0.5, 폭 9)
y 5.24      출처 (좌측 하단만)
좌우 여백 0.5", 카드 간격 0.18~0.2", 카드 radius 0.094"(12px), 카드 안쪽 여백 0.25"
```
- 콘텐츠 영역은 **80% 이상 채운다**. 하단이 비면 INSIGHT 블록 추가 또는 시각 요소 확대
- **INSIGHT 블록**: 박스 없이 상단 헤어라인(hairline-strong) 한 줄 + `INSIGHT` 아이브로우 + 한 문장 (Linear changelog-row 방식)
- 슬라이드 전폭 색 띠, 제목 밑줄, 왼쪽 굵은 세로선 카드, 점선 박스, 표지 그리드 패턴 금지

### 4. 슬라이드 템플릿
| 역할 | 구성 |
|---|---|
| 표지 | 무늬 없는 canvas, 상단 조직·날짜, `// 아이브로우` + 초대형 제목 + 부제, 하단 목차 3개(번호만 accent) |
| 섹션 구분 | 큰 번호 + 섹션명 + 한 줄 설명 |
| 요약 | 3열 카드(업계/사내/다음), 핵심 카드만 surface-2 리프트 + 큰 숫자 accent |
| 데이터 | 좌: 차트 카드(폭 5.6") / 우: 수치 콜아웃 카드 + INSIGHT 블록 |
| KPI | 좌: 2×2 KPI 카드 (가장 중요한 1개만 surface-2 리프트 + 숫자 accent) / 우: 영역별 분류 리스트 또는 다음 단계 |
| 비교·목록 | 우측 세로 카드 3개, 상태 배지(검증 완료/가능성 확인 등) 우측 정렬 |
| 프로세스 | 가로 번호 원(0.5") + 연결선, 현재 단계만 accent 채움, 단계명은 원 아래(연결선과 겹치지 않게), 하단에 백로그 카드 |
| 결론 | 3카드(번호 + 키워드 + 1~2줄) + 하단 요청사항(상단 헤어라인 방식) |
| 클로징 | 표지와 같은 배경, 한 문장 + 연락처 |

### 5. 차트 규칙
- 강조 막대 1개만 accent, 나머지 hairline-strong(`#34343A`). 값 라벨은 막대 안쪽 끝(inEnd), ink, 600
- 기간 적음·단계 비교 → 세로 막대, 항목명이 길면 → 가로 막대(위에서부터 큰 순서), 긴 추이 → 선
- 같은 종류 데이터는 덱 전체에서 같은 차트 형식
- 격자선·값 축 숨김, 범례는 필요할 때만, 차트 배경은 surface-1
- 전후 비교는 카테고리 라벨에 "(70분→5분)"처럼 원값을 넣고 막대는 단축률로

## 출력 형식별 제작법

### PPTX (기본값: 사내 보고·공유)
- pptx 스킬의 SKILL.md를 먼저 읽고 pptxgenjs로 제작
- 차트는 **반드시 네이티브 차트**(`addChart`) — 이미지 차트 금지 (나중에 수치 수정 가능해야 함)
- **막대 1개만 강조하는 법**: pptxgenjs는 막대별 색 지정이 안 되므로, 같은 라벨로 시리즈 2개(비강조 값 / 강조 값, 나머지는 0)를 만들고 `barGrouping: "stacked"`, `chartColors: [muted, accent]`, `dataLabelPosition: "inEnd"`, `dataLabelFormatCode: '0;;;'`(0 숨김)로 그린다
- 색상 값에 `#` 금지, 옵션 객체는 매번 새로 생성, 모든 addText에 `isTextBox: true`
- 차트가 있으면 원본 데이터 `.xlsx`를 함께 제공 (단축률 등은 수식으로)
- **검수 렌더링 전 Pretendard를 설치**한다: `npm i pretendard` → `dist/public/static/*.otf`를 `~/.fonts`에 복사 → `fc-cache -f`. 설치하지 않으면 대체 폰트로 렌더링되어 넘침 검사를 믿을 수 없다
- LibreOffice 미리보기는 한글 옆 쉼표·따옴표 주변에 공백을 넣어 보여준다. PowerPoint에서는 생기지 않으므로 결함으로 보지 않는다
- 전달 시 안내: "Pretendard(SemiBold·Medium·Regular) 기준입니다. 받는 사람에게 PDF로 보낼 때는 PowerPoint에서 파일 → 내보내기 → PDF로 저장하면 폰트가 고정됩니다. PPTX로 공유하면 Pretendard가 없는 PC에서는 다른 폰트로 보입니다."

### Gamma (빠른 초안, 링크 공유)
- Gamma 커넥터의 generate 사용. 입력 텍스트는 기획서의 슬라이드별 `핵심문장 + 근거`로 구성
- 다크 계열 테마를 고르고, 추가 지시에 "배경 #010102, 카드 #0F1011 + 1px #23252A 테두리, accent #00D992 한 가지만, 폰트 Pretendard 600/400, 그림자·그라데이션 없음, 한 장 한 메시지, 수치는 차트로"를 넣는다
- 결과 링크를 주고, Gamma 편집기에서 다듬을 수 있다고 안내

### HTML 웹 슬라이드 (컨퍼런스·교육)
- web-presentation 스킬 사용, 단일 HTML 파일
- Pretendard는 CDN(`cdn.jsdelivr.net/gh/orioncactus/pretendard`)으로 로드
- 방향키 이동, 우측 상단 쪽번호, 위 레이아웃 비율 그대로
- 표지·결론에만 가벼운 모션 (막대가 순서대로 자라는 정도), 과한 애니메이션 금지
- 필요 시 PDF로 변환해 함께 제공

## 다른 브랜드 스타일로 바꿀 때
- `npx getdesign@latest add <브랜드 slug>`로 DESIGN.md를 받는다 (예: `linear.app`, `vercel`, `raycast`). getdesign.md 웹페이지에는 본문이 없으므로 CLI로 받는다.
- 받은 문서의 컬러·타이포·radius·서피스 규칙을 위 1~3절에 매핑한 수정안을 사용자에게 보여주고 승인받은 뒤 반영한다. 폰트는 Pretendard 단일 원칙을 유지한다.

## 금지
- 기획서에 없는 수치·사례 추가 (빈 곳은 `[확인 필요]`, 내 제안은 `[제안]`으로 표시)
- 슬라이드마다 다른 여백·헤더 위치
- 이모지 아이콘, 그라데이션·그림자·글로우, 점선 박스, 색 2개 이상 강조
- 한 텍스트 박스에 모든 내용 몰아넣기 — 굵기·색·크기로 위계를 나눈다
