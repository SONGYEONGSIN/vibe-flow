# Brainstorm: setup.sh — core.hooksPath override 경고

## 의도
- **무엇을**: `setup.sh` 의 hook 설치부(`.git/hooks/post-commit` 배포 직후)에 `git config core.hooksPath` 를 확인해, 비표준 값이면 stdout 에 경고 1줄 출력.
- **누가**: `setup.sh` 를 실행하는 모든 사용자(vibe-flow 설치자) — 특히 전역 dotfiles 로 `core.hooksPath` 를 override 한 사용자.
- **왜 지금**: F-Q12(audit round Q) — `.git/hooks/` 는 git 추적 대상이 아니고, `core.hooksPath` 가 override 상태면 `post-commit` 훅이 배포돼도 실행되지 않아 `commit_pushed` telemetry 이벤트가 조용히 미기록된다(실측: 로컬 197커밋 중 1건만 기록). 감지 없이는 원인 규명이 거의 불가능한 silent failure.
- **성공**: `git config core.hooksPath` 가 설정돼 있으면 `setup.sh` 실행 시 stdout 에 경고 라인이 출력된다. 설정 안 돼 있으면(표준 상태) 경고 없음.

## 제약
- 기술: bash, `git config` 커맨드만 사용(외부 의존성 추가 금지). `set -e` 환경에서 `git config` 미설정 시 비-zero exit 로 스크립트가 죽지 않도록 `|| true` 필요.
- 코드베이스: hook 복사 로직(setup.sh:469-475, `.git/hooks/post-commit` 배포 블록) 바로 다음에 추가 — 관련 로직과 지역성 유지.
- 범위: 경고만 출력(fail 아님) — override 자체는 사용자의 의도된 설정일 수 있어 설치를 막지 않는다.

## 대안 비교

| 대안 | 설명 | 장점 | 단점 |
|------|------|------|------|
| A. 경고 1줄만 출력 | `core.hooksPath` 설정 시 stdout 경고, 설치는 계속 진행 | 최소 변경, 사용자 선택 존중 | 사용자가 무시할 수 있음 |
| B. override 시 자동으로 `core.hooksPath` 를 unset | 강제로 표준 경로 복원 | telemetry 100% 보장 | 사용자의 명시적 git 설정을 임의로 되돌림 — 파괴적, 다른 도구(pre-commit 등) 사용 시 그 워크플로를 깨뜨릴 위험 |

## 추천 + 근거
**A. 경고 1줄만 출력**. `core.hooksPath` 는 사용자가 의도적으로 설정했을 가능성이 높은 설정(예: pre-commit 프레임워크 사용)이라, 자동으로 되돌리는 것(B)은 파괴적이고 범위를 벗어난다. F-Q12 의 요구도 "경고 출력 1줄 추가" 로 명시돼 있어 A가 원안과 일치.
